# compress_numbers

Функция `compress_numbers`, которая удаляет из массива чисел **подряд идущие дубликаты**, и набор автотестов к ней. Python 3.9+, тесты на `pytest`.

```python
>>> from main import compress_numbers
>>> compress_numbers([1, 1, 2, 2, 3])
[1, 2, 3]
>>> compress_numbers([0, 0, 1, 1, 0])
[0, 1, 0]
```

Повторы, которые идут не подряд, остаются: `[1, 2, 1, 2]` → `[1, 2, 1, 2]`.

## Структура

| Файл | Назначение |
|---|---|
| `main.py` | функция `compress_numbers` с докстрингом и doctest-примерами |
| `test_main.py` | основные автотесты (`pytest`) |
| `test_properties.py` | property-based тесты на `hypothesis` (необязательные) |
| `requirements.txt` | зависимости для тестов |

## Запуск

```bash
git clone https://github.com/Lynastra/func-plus-test.git
cd func-plus-test

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

pytest -v                        # все тесты
python -m doctest main.py -v     # примеры из докстринга
```

Если `hypothesis` не установлен, `test_properties.py` автоматически пропускается, остальные тесты работают без него.

## Как работает решение

Один проход по входным данным. Каждый элемент сравнивается с последним добавленным в результат и добавляется, только если отличается от него.

- Время: O(n), память: O(n).
- Возвращается новый список, исходные данные не изменяются.
- Пустой вход обрабатывается тем же условием, отдельная ветка не нужна.
- Принимает любой итерируемый объект: список, кортеж, генератор.

## Что покрывают тесты

**`test_main.py`**
- примеры из условия задачи;
- граничные размеры: пустой массив, один элемент, два элемента;
- серии дубликатов в начале, в конце, в середине, несколько серий разной длины;
- неподряд идущие повторы (чередование) не удаляются;
- отрицательные числа, float, большие int, `inf`;
- контракт функции: вход не мутируется, результат это новый объект, принимаются любые iterable;
- вход на миллион элементов (проверка линейной сложности).

**`test_properties.py`** (случайные данные через `hypothesis`)
- результат совпадает с эталоном на `itertools.groupby`;
- в результате нет соседних одинаковых элементов;
- повторное применение функции ничего не меняет (идемпотентность);
- результат не длиннее входа, первый и последний элементы сохраняются.

## Осознанные решения по краевым случаям

- **`1` и `1.0` считаются дубликатами**, потому что в Python `1 == 1.0`. Поведение зафиксировано тестом.
- **Подряд идущие `NaN` не схлопываются**, потому что по стандарту IEEE 754 `NaN != NaN`. Это тоже зафиксировано тестом, чтобы поведение не стало сюрпризом.
